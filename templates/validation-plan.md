Кейс: `⟨case_id⟩` · revision: `⟨revision⟩` · Дата: `⟨ISO8601 с TZ⟩` · decision ID: `⟨актуальное решение⟩`

## Проверка бизнес-гипотезы

Повтори карточку для каждого experiment ID:

| Поле | Значение |
|---|---|
| id / связанные hypothesis, claim, promise IDs | ⟨IDs⟩ |
| hypothesis | ⟨опровержимое утверждение о поведении и механизме⟩ |
| expected_change | ⟨ожидаемое изменение; минимально полезный эффект и обоснование⟩ |
| Аудитория / единица наблюдения | ⟨критерии включения и кому применим вывод⟩ |
| Вмешательство / контроль / текущий режим | ⟨что получает каждая группа, основание для выбора контроля, отличие контроля от реально действующей практики при наличии⟩ |
| baseline | ⟨измеренная строка/число и источник либо null; неизвестное не ноль⟩ |
| baseline_plan | ⟨обязательный план получения, если baseline=null⟩ |
| metric | ⟨одна главная метрика для решения: числитель, знаменатель, единицы и отсчёт окна. Дополнительные метрики укажи отдельно с их базами⟩ |
| Дизайн / объём | ⟨рандомизация/пилот/наблюдение/интервью; расчёт или ограничения мощности/причинности⟩ |
| timeframe | ⟨старт и длительность набора, окно наблюдения последнего участника, анализ, дата решения и запас⟩ |
| guardrails | ⟨наблюдаемый вред, числитель/знаменатель и окно, сравниваемые группы, источник, численная граница и направление, кто сверяет, при каком результате ставит на паузу⟩ |
| Бюджет | ⟨количество × ставка и итог по каждой статье, известная сумма, лимит, остаток и условия согласования неизвестных затрат⟩ |
| Правило решения | ⟨масштабировать / изменить / остановить / данных недостаточно — заранее заданные условия; при доверительном интервале уровень, метод и сравниваемая граница⟩ |
| Ответственный / ресурсы | ⟨роль; имя владельца только если подтверждено; необходимые разрешения⟩ |
| decision_owner | ⟨подтверждённая роль принимающего решение или null. Что и когда ему передать⟩ |

При закрытии или замене функции перенеси защитный порог и действие при превышении в краткую записку. Если граница предложена, отметь её как допущение для согласования до запуска. [Правило остановки](../methods/validation-and-review.md#порог-остановки-пилота).

### Метрики включения и досрочного отказа

Если пилот проверяет оба события, включи обе строки в план проверки и перенеси формулы в краткую записку. Укажи единицу назначения и отсчёт окна по условиям кейса.

| Метрика по каждой группе | Числитель | Знаменатель | Окно и источник события |
|---|---|---|---|
| Доля включивших | ⟨назначенные единицы, включившие в срок⟩ | ⟨все назначенные в группу, включая пропустивших сообщение. На срезе используют назначения с полным окном⟩ | ⟨срок от назначения, журнал включений⟩ |
| Доля досрочных отказов | ⟨из базы отказались в течение окна⟩ | ⟨в этой группе фактически начали использование или получили первую поставку по определению метрики и имели полное окно к срезу⟩ | ⟨срок от фактического старта или первого получения, журналы старта и отказа⟩ |

## Проверка агента и результатов

| Проверка | Реальный результат / дата / проверяющий | Ограничения / действие |
|---|---|---|
| Структура, source/claim IDs, локаторы, synthetic | ⟨ещё не выполнено / результат⟩ | ⟨structural != semantic truth⟩ |
| Четыре варианта и сильные возражения | ⟨результат⟩ | ⟨что не покрыто⟩ |
| Актуальный ответ человека и options_hash | ⟨результат⟩ | ⟨не подменять молчанием⟩ |
| Две стратегии / promise → capability → evidence | ⟨проверенные фрагменты и смысл⟩ | ⟨ограничения⟩ |
| Расчёты / входы / единицы / provenance | ⟨результат⟩ | ⟨synthetic явно⟩ |
| Пауза / новый чат / новый факт / инъекция | ⟨что реально пройдено⟩ | ⟨механический тест и живой прогон различать⟩ |

Найденные ошибки и исправления: `⟨содержание⟩`. Неустранённые ограничения: `⟨содержание⟩`. Готовность текущей версии / next_action: `⟨обоснование, без объявления рыночного успеха⟩`.

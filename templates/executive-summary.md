# Краткий итог решения

Шаблон для `outputs/executive-summary.md`; `⟨…⟩` не заполнено. Держи основной итог на одном экране; доказательства открываются по ID и артефактам.

Кейс: `⟨case_id⟩` · revision: `⟨подтверждённая revision⟩` · Дата: `⟨ISO8601 с TZ⟩` · Статус: `⟨черновик / awaiting_human / needs_review / завершена текущая версия⟩`

**Решение:** `⟨что выбрано, для кого, почему сейчас; допустим отказ/отсрочка⟩`. Участие человека: `⟨decision ID, выбранный option, реальный ответ/ссылка на запись; если ответа нет, явно указать⟩`.

Три главных основания: `⟨claim IDs и ограничения⟩`. Сильнейшее возражение: `⟨почему может быть ошибкой⟩`. Уверенность / цена ошибки / условие смены решения: `⟨конкретно⟩`.

| Результат | Главное | Подробности |
|---|---|---|
| Исследование | ⟨что подтверждено / спорно / неизвестно⟩ | ⟨evidence и source/claim IDs⟩ |
| Продуктовая стратегия | ⟨выбор, механизм ценности, сознательные отказы⟩ | ⟨product-strategy⟩ |
| Коммуникационная стратегия | ⟨аудитория/барьер/сообщение/роль каналов; допустимые обещания⟩ | ⟨communication-strategy и promise IDs⟩ |
| Проверка результата | ⟨baseline или получение; metric, срок, правило решения, guardrails⟩ | ⟨validation-plan и experiment IDs⟩ |

Пробелы и ограничения: `⟨официальный бриф / данные / синтетика / формат / причинность / самопроверка⟩`. Что реально проверено: `⟨структурно и содержательно; тесты не доказывают рыночный результат⟩`.

Ресурс: `⟨измеренное время, доступное имя модели/режим, известный расход квоты; неизвестное явно⟩`. Следующее действие / владелец: `⟨обратимый шаг или требуемое решение⟩`. Пересмотр при: `⟨новом факте/условии/дате⟩`.

Сохранение: `⟨проверенный checkpoint/revision; незавершённое действие отдельно⟩`. Завершение этой версии не означает успешный запуск, публикацию или готовность конкурсного комплекта.

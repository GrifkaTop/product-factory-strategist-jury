# Пересмотр решения после эксперимента

Проверь кейс через `status` и `review`. Для новой проверки до импорта результата сохрани протокол по сценарию `prompts/decision-lab.md` из корня проекта. При отсутствующем или позднем протоколе объясни ограничение и предложи следующий корректный замер.

Вызови `python -m tools.strategist outcome --case CASE --experiment EXP --source SOURCE`. В пересмотренной записке приведи `outcome_reconciliation` по обеим группам, наблюдаемый эффект в п.п., границы по пропускам и доверительный интервал отдельно. Укажи, как сверить назначения и осталось ли что-то неизвестным в каждой группе. Для требования к ДИ явно выпиши нижнюю границу, знак сравнения и численный порог из `lower_bound_comparison`, включая сравнение по предварительному интервалу. Отдельно укажи статус интервала по всем назначенным. При превышении защитного порога сначала разберись с риском.

Передай владельцу решения сверку, пересчёт, предложения по обеим стратегиям и условие повторного рассмотрения. Если роль неизвестна, уточни её. Привяжи правки к ID эксперимента и источнику. Учебный результат обозначь на всём пути. Сохраняй отчёт через `--save` в рамках разрешённой работы. Новый существенный выбор передавай человеку.
